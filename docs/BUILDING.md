# Building and running

Everything in this repository is plain C++20. There are two ways to build it:
CMake (recommended, builds every example) or a direct compiler command (best
when you are studying one file).

## Prerequisites

| Tool | Version | Notes |
| --- | --- | --- |
| C++ compiler | C++20 | GCC 11+, Clang 14+, or MSVC 2022 |
| CMake | 3.16+ | Any recent version works |
| Make or Ninja | any | Generated by CMake |

Check your compiler:

```bash
g++ --version      # or clang++ --version
cmake --version
```

## Quick start with CMake

From the repository root:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

All programs are written to `build/bin/`.

Run the guided tour:

```bash
./build/bin/dsa_demo
```

Run a specific example:

```bash
./build/bin/algo_dijkstra
./build/bin/ds_kd_tree
./build/bin/algo_miller_rabin
```

### Useful CMake options

| Option | Default | Meaning |
| --- | --- | --- |
| `DSA_BUILD_DEMOS` | `ON` | Build the standalone example programs |
| `DSA_BUILD_TESTS` | `ON` | Build the tests and register them with CTest |

Example: build only the tests

```bash
cmake -S . -B build -DDSA_BUILD_DEMOS=OFF
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

## Build one file without CMake

Header-only algorithms can be compiled directly:

```bash
g++ -std=c++20 -Isrc src/demos/main.cpp -o dsa_demo
./dsa_demo
```

To study a single algorithm, create a small file that includes it:

```cpp
#include "algorithms/sorting/bubble_sort.h"
#include <iostream>

int main() {
    int values[] = {5, 1, 4, 2, 3};
    bubbleSort(values, 5);
    for (int value : values) std::cout << value << ' ';
}
```

```bash
g++ -std=c++20 -Isrc my_experiment.cpp -o my_experiment
```

## Windows

### Visual Studio / MSVC

The examples use the GNU header `<bits/stdc++.h>` in a few files. When CMake
detects MSVC it automatically adds `src/compat` to the include path, where a
small compatibility header lives. Use the normal CMake commands:

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

### MinGW / MSYS2

```bash
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build --parallel
```

### PowerShell helper

`scripts/build.ps1` is the original Windows helper. It wraps CMake and can
optionally launch the Visual Studio debugger:

```powershell
. ./scripts/build.ps1
Build-And-Run -Clean -Config Release
Build-And-Run -Debug -DebugFile src/demos/main.cpp -DebugBreak 10
```

## macOS

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

Apple Clang does not ship `<bits/stdc++.h>`. If you hit a missing-header error,
configure with the compatibility include path:

```bash
cmake -S . -B build -DCMAKE_CXX_FLAGS="-Isrc/compat"
```

## Editing in an IDE

- **CLion / Visual Studio / VS Code:** open the repository root and let the IDE
  use the generated `build/compile_commands.json` (configure with
  `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`).
- **Code style:** `.clang-format` is included. Run `clang-format -i <file>` if
  you have it installed.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `bits/stdc++.h: No such file` | Use GCC, or add `-Isrc/compat` (see macOS) |
| `undefined reference to main` | That `.cpp` is a library/implementation; build the matching demo target |
| CMake picks an old compiler | Delete the build folder and configure again |
| Build folder contains old paths | Delete it: `rm -rf build` and reconfigure |
| Tests fail after editing | Run `ctest --test-dir build --output-on-failure` to see the exact case |
